# Цикл 7 — H2 TAQ: карантин документов; операторская остановка

Цикл построен вокруг идеи: **TAQ — прерывание по порогу τ + детерминированная атрибуция документа по частичной трассе + карантин + один повторный проход**. Обязательный первый gate — G-break: проверка гипотезы H1-sufficient («инструкции достаточно») адаптивной атакой на B-sys.

### 1) Постановка и протокол

| Решение | Описание |
|---|---|
| **Контекст из ц.6** | Приманка в документе снижает B-cap(C=8192) 0.750→0.183; BEIS опровергнута; B-sys 0.742 — пост-хок. Критик ц.6: факторный {user,system}×{generic,specific} с равной адаптацией. |
| **Протокол (заморожен)** | 13 baselines (D0, NOCTX, B-big, B-base, 4 факторные ячейки, B-stop, B-rerun, B-cap-match, B-randq, B-imper, B-relq, TAQ, TAQ-oracle); gates G0/G1/G-τ/G-break/G-attr/G3; falsification F1–F6; PC1–PC6; бюджет ≤ 42 000 вызовов / ≤ 91 usage units. |
| **Данные** | HotpotQA (split c06 реконструирован, holdout_primary совпал с 120 id ц.6) + вторая коллекция 2WikiMultihopQA (Apache-2.0): dev_second_calib 20, holdout_second 80. |
| **F0** | При finish=length в non-stream возвращается `message.reasoning` (1019/3956 символов), content пуст; clean completion до 7 754 — риск для G-τ. |

### 3) Найденный и исправленный дефект

| Решение | Описание |
|---|---|
| **finish_reason=error при HTTP 200** | Провайдер обрывал генерацию с пустым content, а клиент считал это успехом → fail-closed завышал эффект атаки. Исправлено: транспортный retry, пересчёт исходов, тест `test_finish_error_in_200_is_transport_and_retried`; затронутые вызовы повторены как тот же вызов (не новые наблюдения). Тесты: 85+10 passed. |

### 6) Итог

- **Вердикта по подтверждению нет** — данные неполные по решению оператора. На dev опровергнуты обе гипотезы: H2-TAQ (G-τ: 20–22.5% ложных прерываний, все карантины удаляют supporting-документ) и H1-sufficient (G-break).
- **Побочные продукты**: G-tau как обязательный gate для любого механизма прерывания; B-big — сильный baseline доступности, но с утечками канарейки; обнаружение finish_reason=error; seccomp/verify-обвязка.
- **Следующее направление**: разделение осей доступность/целостность — большой cap + детерминированная проверка целостности + бюджет арендатора.
