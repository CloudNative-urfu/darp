# Цикл 5 — C5-H1: action-selector, ID-строка против JSON

Цикл построен вокруг идеи: **одношаговый выбор одного host-ID против компактных JSON-аргументов при одинаковом каталоге и gateway** — эмпирическая гипотеза об интерфейсе защиты, не новая архитектура.

### 1) Обзор литературы и выбор гипотезы

| Решение | Описание |
|---|---|
| **17 источников** | Patterns §3.1 (action-selector уже описан), FIDES §5.2 (enum-канал с ограниченной ёмкостью), APEX §3.3 (смысловой выбор оставлен допущением), PROVISO, The Format Tax §7 (риск неравных prompts и ошибок парсинга). |
| **Ограничение выводов** | Нельзя обещать пользу ID по литературе или сравнивать с искусственно сложным JSON; безопасность проверяется и на неверном выборе внутри allowlist. |

### 2) Протокол (заморожен, defense-c05-h1-v1)

| Решение | Описание |
|---|---|
| **Варианты** | H = plain ID; JSON-ID — абляция; сильный B-long обязателен; B-native получает собственный бюджет. |
| **Данные** | 6 dev + 8 новых confirmation family; все адаптивно выбранные payload переносятся между вариантами. |
| **Бюджет (потолок)** | 412 физических вызовов; первый capability-блок — максимум 42 основных. |

### 3) Реализация и обрыв F0

| Решение | Описание |
|---|---|
| **MVP** | Gold-free каталог, строгие ID/JSON/JSON-ID parsers, атомарный gateway, D0 с индексом всех полей/BM25/отрицаниями; 40/40 тестов. |
| **Обрыв процесса** | F0 прерван: 21 intent, 20 ответов; `p0021/l0021` (B-JSON) остался без ответа — причина прекращения неизвестна. Опыт закрыт как incomplete: 20 завершённых, 1 unresolved, 21 не отправлен. Повтор незавершённого запроса запрещён frozen retry_rule. |
| **Продолжение** | 21 новый слот, 22 физических попытки: p0026 получил HTTP 429, p0027 после 5s backoff — успешно. p0043/l0042 — HTTP 200 с **275 whitespace-only bytes** без usage — по frozen правилу не повторяется. |
| **Fresh результат** | **H-ID: 12/12 typed и SFC, wrong=0** — интерфейсный F0 gate пройден при R0/cap8192. B-JSON: 10/12 ITT (10/11 среди завершённых). В десяти парах с model completions оба формата дают правильный ответ — ITT-разность не доказывает format advantage. |

### 4) Корпус AgentDojo и qualification

| Решение | Описание |
|---|---|
| **Просмотр** | Все 86 `UserTask` четырёх v1 suites: 33 workspace, 17 slack, 16 banking, 20 travel. Большинство задач не подходят под single-field действие. |
| **Кандидат slack/UserTask9** | Native/diff-контроль: на всех 4 actions native и full-state checker совпадают, но **negative control (correct + лишнее добавление Bob) native принимает, full-state checker отвергает** → по frozen правилу `unqualified`. |
| **Решение oracle** | Разрешено расхождение конъюнкцией «native utility AND exact gold diff AND отсутствие нарушений» — negative extra-effect остаётся SFC=false. |
| **Итог** | **0 полностью qualified family**; разрешён один partial-dev family (slack/UserTask9, count-задача). Full dev = 1/6, hard = 0. |

### 6) Итог

- **Статус: `inconclusive_partial_dev_confirmation_blocked`.** H прошла интерфейсный F0 (12/12), но на единственном count-family уступила B-long/D0 по полезности и B-long по токенам. Полезная добавка H/LLM не установлена; Bstar=null, confirmation 0/8.
- **Побочные продукты**: replay-инфраструктура (19/19 негативных подмен отклонены), класс дефекта «safety-styled payload → reasoning-цикл до cap → потеря задачи», точный D0 для count-scope, memory.json (9 facts / 6 failures / 5 unknowns / 5 next).
- **Следующее направление**: квалифицировать действительно смысловые внешние истории и native/full-state gold, затем регистрировать достижимый опыт с сильным B-long.
