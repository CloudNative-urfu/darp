# Shield to Target (Denial-of-Service Attacks on LLM-Based Agent Guardrails) [arXiv 2606.14517] — дизассембли методологии
Verdict: Partially portable. Методологический каркас самый близкий из четырёх к полигону: guardrail на критическом пути агента, замер compute/latency per guardrail-call, разбивка издержек, деградация пропускной способности у со-хостящихся агентов (прямой аналог Q) — но публичный код не найден, а основные результаты стоят на закрытых моделях (proposer GPT-5.2, таргеты Claude/GPT-4o-mini). Портируемость: методология без кода, воспроизводимость — по тексту (константы расписаны).
По-простому: Авторы строят payload'ы, которые «залипают» guardrail: тот часами носится с рассуждениями, тратит в десятки и сотни раз больше токенов и тормозит соседних агентов на той же очереди.
## 1. Harness
- Двухуровневая схема: (a) standalone — beam-поиск payload'ов через white-box surrogate TS-Guard-8B, затем перенос без адаптации на 8 целевых guardrail-бэкбонов: TS-Guard-8B, Qwen3.5-9B, DeepSeek-V3.2, GLM-4.7, Kimi-K2.5, Claude-3.5-Haiku, GPT-4o-mini, Gemini-3-Flash: «Payloads are optimized on a single surrogate model (TS-Guard-8B) using our beam-search framework and evaluated on 8 target guardrail models spanning open-source and closed-source families. TS-Guard-8B is a representative open-source guardrail with full output observability, enabling efficient fitness evaluation during optimization.»
- (b) end-to-end: OpenHands (код-агент + интегрированный LLMSecurityAnalyzer), LangGraph+NeMo Guardrails (виртуальный межагентовый rails + Qwen3.5-Flash), BrowserGym+WebGuard (per-action JSON-вердикт), OSWorld+ShieldAgent (Qwen2.5-7B, 3 проверки на действие в теории); агенты: DeepSeek-V3.2 (код), GPT-4o-mini (multi-agent, web): «We instantiate our attack across four real-world agent scenarios: code agents, multi-agent systems, web agents, and desktop agents. Each represents a distinct agent type, guardrail architecture, and injection surface.» OpenHands — интегрированная архитектура: «OpenHands' safety module (LLMSecurityAnalyzer) operates within the agent's own LLM: a security_risk parameter ("LOW"|"MEDIUM"|"HIGH") is injected into every tool's JSON schema.» NeMo rail: «We deploy a NeMo output rail with a moderate size reasoning model backend Qwen3.5-Flash that uses a structured prompt with <Think> reasoning followed by a <Harmfulness_Rating> verdict.» WebGuard per-action: «outputting a structured JSON verdict: {"thought": "...", "risky_level": "SAFE|LOW|HIGH"}. Each action is evaluated independently with no cross-step memory.»
- Замеры: длина reasoning-секции <Think>…</Think> в символах, latency per guardrail call (сек), tokens per task, throughput при head-of-line blocking: «Attacked thinking length measures the total character count within the guardrail's reasoning section (<Think>…</Think>) under attack, capturing the absolute compute burden imposed on the safety model.» Latency — до 148.2×, «730.8 seconds for a single guardrail call»; серверы NVIDIA RTX5880: «All experiments are conducted on a group of NVIDIA RTX5880 GPU servers.» Docker/виртуализация — not stated.
## 2. Источники и срез данных
- Standalone: три бенча — AgentDojo (tool-use со встроенными инъекциями), ASB (категории рисков), AgentHarm (explicit вредные действия); payload-инъекции поверх готовых bench-контекстов, собственный датасет атак не нужен: «AgentDojo is a tool-use agent benchmark with built-in injection attack scenarios… ASB is a safety benchmark covering diverse agent safety scenarios across multiple risk categories… AgentHarm is a benchmark of explicitly harmful agent behaviors.»
- End-to-end: 20 SWE-bench-инстансов (Django/scikit-learn/matplotlib) для код-агента: «We evaluate on 20 SWE-bench instances covering real GitHub issues from Django, scikit-learn, matplotlib, and other popular repositories using DeepSeek-V3.2 as both agent and guardrail model.»
- Multi-agent: 25 задач в 5 доменах (Financial/Healthcare/Legal/Software/OSINT): «Agent workers use GPT-4o-mini across 25 tasks in 5 domains Financial, Healthcare, Legal, Software Development, Open-Source Intelligence (OSINT).» Web: 10 WebArena shopping-задач на собственном Flask e-commerce сайте (10 страниц): «We deploy a custom Flask e-commerce site with 10 pages and evaluate 10 WebArena shopping tasks (search, add to cart, checkout, account management).» Desktop: 20 случайно отобранных OSWorld сценариев: «We randomly select 20 representative scenarios» — чистка/фильтрация сэмплов и seeds отбора не описаны — not stated.
## 3. Протокол фиксации исходов
- Вердикт фиксируется до токена: r_t = (φ_t, v_t), v_t ∈ {allow, block} извлекается парсером; длина |φ_t| — основная мера нагрузки. Отказ «no verdict»: успешные loop-случаи отмечены «*» = sustained reasoning loops >10 повторений — guardrail зациклился и вердикт не достигнут: «Entries marked with * indicate sustained reasoning loops, which would consume unbounded compute without generation length limit.»
- Extension ratio = attacked think length / baseline think length на length-matched benign input — изолирует эффект от длины запроса: «Extension ratio is the ratio of attacked thinking length to the baseline thinking length on a length-matched benign input, isolating the amplification effect from any length-induced increase.» 4 условия web-агента — fail-open vs fail-closed как два зарегистрированных исхода: «the guardrail evaluating each action under four conditions: (1) baseline (clean site), (2) attack without timeout, (3) attack with 30-second timeout defaulting to allow, and (4) attack with 30-second timeout defaulting to block.» «Under timeout-block, 34 out of 55 total actions are blocked, reducing task success to 3/10 and effectively denying service. Any fixed timeout policy thus creates an exploitable binary outcome.» Q-аналог: throughput degradation 23.3% и ожидание 113–146 s у benign-воркеров при supervisor-паттерне — очередь замеряется как деградация пропускной способности shared-guardrail; state-persistence: «Second, the trigger persists: a poisoned README.md or config.py remains in the repository and affects future agent sessions, including those launched by other developers.»
## 4. Учёт затрат
- Столбцы: token amplification (раз), latency amplification (раз), «same wall-clock budget» ablation: «All variants run for the same wall-clock budget.» Стоимость атаки per variant $0.46 → $0.07 при переходе на Inst. II: «This reduces per-variant generation cost of attacker's budget by 6.6× from $0.46 to $0.07, while preserving considerable amplification and enabling mass poisoning of heterogeneous repositories.»
- Breakdown: (per-action guardrail call count) × (per-call latency) по multi-step: «a typical SWE-bench task requires 15–30 actions, each invoking the security analyzer. With README injection, this raises guardrail overhead from ~138 seconds to over 59 minutes for a single task.» → NFR-2.9: атакующий бюджет vs defender-издержки фиксируются раздельно; GPU-часы proposer'а — только «Iters to Peak», not stated.
## 5. Статистика
- Seed-контроль оптимизатора: «The random seed baseline (2,195) is near the benign baseline, confirming that optimization drives the attack's effectiveness.» Повторы ключевых замеров (standalone, ablation, web-таймауты) — not stated.
- Ablations при same wall-clock: beam k=1 vs 5, diversity δ=1.0, strategy bank: «greedy search (k=1) achieves only 7,220, an 88% drop from the full framework… removing diversity filtering drops fitness to 45,513 (23% reduction)… and removing the strategy bank drops to 43,896 (26% reduction).» Proposer-модель GPT-5.2 → GPT-4o-mini → Claude → DeepSeek → Qwen3.5-9B → mechanism-aware без LLM: «GPT-5.2 achieves the highest fitness 59,182… Smaller models (e.g., Qwen3.5-9B at 37,071 fitness) still achieve substantial amplification but require more iterations. The mechanism-aware instantiation also achieves 33,895 fitness with 15 iterations.» Компонентный вырез payload'а — анти-shortcut/enumeration/depth: «− Anti-shortcut clauses 5,776 83.0%; − Category enumeration (S1–S9) 8,760 74.2%; − Enumeration depth (reduce to 1) 6,424 81.1%.» Перенос: те же payload'ы на 3 шаблонах ToolSafe/TaskShield/MELON — «all above 20×»: «As shown in Table VI, all results remain above 20× amplification across different configurations.»
## 6. Trap-деталь
- Где застревает повтор: fine-tuned classifier guardrail ShieldAgent (обученный EOS ~170 токенов на проверку) взламывается генерационной дорожкой: «Unlike reasoning models that produce extended <Think> traces, ShieldAgent emits a brief [Analysis] followed by a binary [Answer] safe/unsafe verdict, and its fine-tuned EOS behavior naturally caps output at ~170 tokens per check. We exploit it by forcing continued generation past its trained stopping point.» + схема schema-priming своим S1–S9 чеклистом: «Combined with schema-priming payloads that present ShieldAgent's own safety taxonomy (S1–S9) as an enumerated checklist, the model fills forced output with structured analysis rather than degenerate repetition.» → 18.42× token amplification на Qwen2.5-7B.
- Интегрированный guardrail (same LLM = agent) требует другого payload'а — не template-following, а contradictory security factors: «we try to force the model to generate a useful action and assess its security risk at the same time. By presenting contradictory security factors that resist simple resolution, we force extended deliberation rather than extended enumeration.»
## Прямой перенос
- Guardrail = критический путь + cost-per-call: «At 131× amplification, a guardrail call that should complete in 10 seconds instead takes 21 minutes, far exceeding any practical timeout and rendering the safety system non-functional for the duration of the task.» → C_guard по FR-1.17; latency-бюджет как операнда L*; extension ratio на length-matched benign — прямой paired-контроль NFR-2.8.
- Per-surface атрибуция — протокол «замер каждой поверхности отдельно»: «Among all possible injection surfaces, the README surface achieves the strongest and most consistent amplification (25.9× mean, all tasks above 3×)… The config surface achieves 11.9× mean amplification (peak 20.7×)… The code comment surface shows weaker amplification (5.5× mean).» Tool output 115.8× > shared memory 4.3× > user instruction 1.6×: «confirming that surfaces closer to external data sources are more vulnerable.» → FR-1.17, FR-1.21
- Fail-open/fail-closed как двойной замер фиксированной таймаут-стратегии (34 из 55 действий заблокировано) → FR-1.23, FR-1.15; offline-оптимизация (white-box surrogate) → замороженный payload → NFR-2.10/NFR-2.11.
## Адаптация
- Surrogate через open ≤8B (TS-Guard-8B, ShieldAgent Qwen2.5-7B) совместим с NFR-2.4/2.5/2.6; proposer GPT-5.2 заменяем — Qwen3.5-9B-as-proposer и mechanism-aware без LLM: «Smaller models (e.g., Qwen3.5-9B at 37,071 fitness) still achieve substantial amplification but require more iterations.»
- Structural mutation Inst. II (slot-представление + операторы мутаций, 6.6× дешевле) переносится целиком на локальный guardrail — слоты: «define slots including risk categories, enumeration depth, analysis sections, anti-shortcut clauses and define mutation operators» → бюджет атакующего → FR-1.21; максимальные эффекты упираются в generation cap: «The tool output and agent message surfaces achieve up to 115.8× token amplification, i.e. 82,000+ tokens, hitting the generation cap, and 148.2× latency amplification, i.e. 730.8 seconds for a single guardrail call.»
## Непереносимо
- Закрытые таргеты (Claude-3.5-Haiku, GPT-4o-mini, Gemini-3-Flash) и закрытый proposer GPT-5.2 — вне NFR-2.4: «GPT-5.2 achieves the highest fitness 59,182 and converges fastest in 6 iterations»; «Claude-3.5-Haiku reaches 27.7×, Gemini-3-Flash 22.1×, and GPT-4o-mini 20.6× on AgentDojo (Inst. I).»
- Бейзлайны OverThink/ReasoningBomb/CRABS/RECUR†/ThinkTrap† — partial reproduction без оригинального кода: «† = partial reproduction (code not released).» «All six baselines achieve only 1.11–1.20× amplification, which are well within the normal variance of guardrail reasoning length.» Собственный Flask e-commerce сайт (10 страниц, 10 WebArena-задач) — кастомная посадка, изоляция/воспроизводимость не описаны.
## Что осталось непонятным
- Повторы/CI по всем ключевым замерам (основной standalone-лидерборд, web-таймауты, ShieldAgent EoS) — not stated; особенно end-to-end при 10–25 задачах per condition.
- Полный состав strategy bank (100+ паттернов) не опубликован — названы три: «"categorical exhaustion," "anti-convergence clauses," "schema mimicry")» — not stated.
- Что такое ω (вес attention-штрафа) в Fitness = F_base(p) + ω·A(p) и порог top-N для расчёта A(p) — численно not stated: «design a transform-aware fitness function…» — ω не дана.
- Отбор/матчинг benign baseline контекстов (как устроен length-matched benign) — описано словесно, без алгоритма/скрипта — not stated.
- Методика latency замеров (CPU profiling? per-step timestamps?) не описана, возможно не включается в queueing time — not stated.
- Как вычислялась throughput-деградация benign при supervisor (23.3%): «one poisoned worker consumes 12+ minutes of guardrail time, causing 23.3% throughput degradation and 113–146 seconds of waiting for benign workers» — batch/continuous, число повторов — not stated.
