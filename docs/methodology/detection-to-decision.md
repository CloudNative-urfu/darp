# From Detection to Decision: Calibration and Deferral for Prompt-Injection Detection [arXiv 2610.20907] — методологический разбор

Verdict: Fully portable. Протокол «frozen evaluation» (dev/calibration/confirmatory сплиты + заморозка всего до confirm-прогона) переносится как есть и структурно совпадает с нашими NFR-2.10/NFR-2.8; код с офлайн-артефактами предсказаний воспроизводит все таблицы без API. Связь переносимости: публичный код https://github.com/lanqianlong/calibrated-decision-models — 47 611 выровненных записей предсказаний, воспроизведение скриптом, `scripts/reproduce_all.sh`.
По-простому: авторы построили конвейер из детектора и авто-решения: гейт оценивает вероятность атаки и ведёт риск к решению (ALLOW/DEFER/BLOCK), где DEFER — передача спорного примера живому LLM-рецензенту. Всё (модели, промпты, пороги) заморожено до финального confirm-теста, чтобы порог не «подсматривал» ответ.
## 1. Harness
- Стенд — не агент, а конвейер «gate → фикс-политика → reviewer»: замороженный гейт скорирует confirm-примеры, фиксированная политика маппит p(attack) в ALLOW/DEFER/BLOCK, только DEFER уходит замороженному LLM-рецензенту: «Each confirmatory input is scored by a frozen security gate, and a fixed policy maps the resulting attack probability to ALLOW, DEFER, or BLOCK. Only deferred inputs are sent to the frozen LLM reviewer, which produces the final decision»; confirm-кохорт шёл без дотюнинга: «The confirmatory cohort is evaluated without further tuning.»
- Три семейства детекторов в связке — Jev-native и Prompt Guard 2 (22M/86M) против frontier-судьи GPT-5.5: «We use GPT-5.5 as the LLM judge. We compare three prompts on an independent 1,000-example development split and select one that asks for an attack probability, a binary decision, and a short rationale»
- Confirm-кохорт шёл в «as-is» режиме: без дотюнинга и повторных решений по его лейблам: «The confirmatory cohort is evaluated without further tuning.»
- Изоляция каскадом сплитов: промпты моделей и рецензента — на dev-сплите; температуры и интервалы гейта — на gate-calibration (2 000 примеров); температура и порог рецензента — на reviewer-calibration (1 000); confirm-кохорт с ними не пересекается: «Gate temperatures and ALLOW–DEFER–BLOCK intervals are fitted on a 2,000-example gate-calibration split, while the reviewer temperature is fitted on a separate 1,000-example reviewer-calibration split ... The calibration and confirmatory sets are disjoint» → NFR-2.10.
- Измеряется система целиком (дискриминация, калибровка, latency, кривые деферрала), не гейт отдельно: «We jointly evaluate discrimination, probability calibration, confident false negatives, latency, and operational security-deferral behavior» — версии: Python 3.9.21, NumPy 2.0.2, SciPy 1.13.1, scikit-learn 1.6.1: «The implementation uses Python 3.9.21, NumPy 2.0.2, SciPy 1.13.1, and scikit-learn 1.6.1»; контейнеры/GPU-изоляция — not stated.
## 2. Источники и срез данных
- 4 публичных бенчмарка, выбранных до confirm-прогона (TensorTrust 0 benign / 526 attack; BIPIA 53 / 36 075; NotInject 89 / 0; PIDS-Bench v3 5 488 / 5 380) — итого 47 611 (41 981 attack / 5 630 benign), искусственно несбалансированная смесь (88.2% атак): «The pooled test set is deliberately heterogeneous and highly imbalanced, with 41,981 attacks and 5,630 benign examples. We therefore report both pooled and dataset-level metrics»; сами семейства отобраны до confirm-прогона: «We use four benchmark families selected before the confirmatory run»
- Отдельной чистки/дата-клининга не описано — not stated; конвертации/трансформации бенчмарков упомянуты как источник зависимости между примерами: «Benchmark transformations may also introduce dependence among examples, so small numerical differences ... should not be treated as statistically resolved»
## 3. Протокол фиксации исходов
- Исход — объективное решение системы по каждому примеру (allow/block/defer) против gold-лейбла; состояние defer записывается явно: вне эскалационного интервала гейт решает сам, дефералы уходят рецензенту за финальным решением; связки (ties) вероятностей сдвигаются вместе: «the gate handles an input automatically unless it falls within the escalation region. Deferred inputs are passed to the frozen LLM reviewer for the final decision, and tied probabilities are moved together»
- «Эмпирическое confirm-требование эскалации» = минимальная доля эскалаций на кривой деферрала, при которой FNR ≤ 1%: не deploy-порог — аналог L*/FR-1.24, но «сколько очереди нужно», а не break-even: «On the frozen confirmatory cohort, the empirical deferral curves satisfy FNR ≤ 1% only when more than 91.8% of inputs are escalated, with substantial false-positive rates»
- Метрики поверх вердикта: помимо AUROC/AUPRC в отчёте FPR, автопокрытие, иллюстративный cost и latency: «We also report FPR, automatic coverage, illustrative expected cost under (C_FP, C_FN, C_review) = (1, 100, 0.5), and latency» → FR-1.23.
## 4. Учёт затрат
- Единицы иллюстративные: (C_FP, C_FN, C_review) = (1, 100, 0.5), нормированная cost — среднее по примерам на кривой деферрала, все цены безразмерные: «The cost model (1, 100, 0.5) is illustrative, and deployment policies should instead be selected using application-specific costs and review budgets».
- Разбиение есть: FPR системы, автопокрытие, cost и latency точки пересечения дают издержки гейта, очереди и рецензента раздельно → NFR-2.9; латентность mean/p50/p95 на пример по компонентам: PG2-86M 43.8 мс; PG2-22M 45.8; Jev 190.9; LLM-рецензент 3 890.2 — очередь упирается в скорость рецензента: «The local Prompt Guard models are roughly two orders of magnitude faster than the remote LLM reviewer.» → FR-1.16; деньги/токены — not stated.
## 5. Статистика
- Повторения/семена/CI не проводятся и не заявлены — точечные оценки, авторы признают это сами: «We report point estimates without confidence intervals.» — SEM/CI по подвыборкам добавим поверх их протокола (NFR-2.8).
- Контролы: непересечение dev/calibration/confirm; temperature-масштабирование монотонно ⇒ у raw и calibrated совпадают AUROC/AUPRC и кривые деферрала — встроенный контроль: «Raw and temperature-scaled Prompt Guard curves overlap because scalar temperature scaling preserves uncertainty ordering.»; отказ интерпретировать разницу < 1 п.п. между гейтами; датасет-левельная калибровка против composition-эффектов: «Pooled metrics can obscure composition effects. The confirmatory cohort is dominated by attacks from BIPIA»; оракул/закрытие при сбое — контрольные ablation, не deploy-результаты: «Oracle and fail-closed review are included only as ablations.»; пул несбалансирован — выводы нельзя лить на естественную распространённость: «The confirmatory mixture does not reflect a natural production prevalence, and its pooled calibration and cost results should not be transferred directly to deployment settings.»
## 6. Trap-деталь
- Что ломается при reproduce: слабый операционный порог рецензента съедает выгоду деферрала — frozen-артефакты названы точно (промпт llm-judge-candidate-effect-v1, температура 1.590979, порог 0.052738 с FNR=0 / FPR=98.6% на калибровке): «The reviewer prompt is llm-judge-candidate-effect-v1. Its scalar temperature is 1.590979 and its frozen calibrated-probability threshold is 0.052738» / «has an FPR of 98.6% on the reviewer-calibration split»; на точке FNR≤1% блокируется 40–46% benign: «The system FPR remains between 40.6% and 45.8% at these crossings, showing why FNR alone is not sufficient to characterize the resulting policy»; очередь калибровать отдельно от её пропускной способности.
- Confident-FN: средняя p(attack) на пропущенных атаках — контроль «missed at high confidence»; temperature-scaling смягчает вероятности, но не возвращает пропуски на границе 0.5: «Among attacks missed by raw PG2-86M, the mean assigned attack probability is only 0.0107 ... Temperature scaling makes these probabilities less extreme but does not recover the missed attacks at the fixed 0.5 boundary»
## Прямой перенос
- Каскад dev / gate-calib / reviewer-calib / confirmatory сплитов с заморозкой: «All models, prompts, calibration parameters, the reviewer threshold, and deployable gate intervals are frozen before confirmatory evaluation. Confirmatory labels are never used to select a deployable threshold» → NFR-2.10, NFR-2.8.
- «Empirical escalation requirement» на кривой деферрала как descriptive-статистика → FR-1.24, FR-1.15, FR-1.19.
- Latency mean/p50/p95 по компонентам с разделением local/API-накладных: «Because the API measurements include network and provider overhead, these latency values characterize the evaluated deployment setup rather than model-only computation» → NFR-2.9; отчёт и pooled, и per-dataset при несбалансированной смеси → FR-1.23.
## Адаптация
- Cost-triple (1, 100, 0.5) заменяем на C_break / C_refuse / C_guard с волнами нагрузки по нашему cost journal → FR-1.17, NFR-2.9; требуемую долю эскалаций связать с нашей Q и E → FR-1.15, FR-1.16.
- Рецензент GPT-5.5 / Jev API закрыты → OSS ≤8B с той же заморозкой и калибровкой temperature-scaling: «The verbalized probabilities are temperature-scaled on a separate 1,000-example reviewer-calibration split» → NFR-2.1, NFR-2.10.
## Непереносимо
- Hosted Jev через TypeSafe SDK — закрытая модель, часть «decision model» не разворачивается локально: «Our reviewer has the strongest discrimination among the evaluated models, but its FNR-first operating point also produces a very high FPR»; повторов/семян/CI нет — наши требования NFR-2.8 и NFR-2.11 придётся достраивать самим: «We report point estimates without confidence intervals.»
## Что осталось непонятным
- Как строились confirm-подмножества из бенчмарков (sampling, стратификация) — not stated, известен только итоговый размер пула (47 611 записей).
- Инфраструктура запуска локального инференса PG2 (железо, контейнеризация) — not stated: «Latency is measured in the evaluated combination of local and API-based inference without normalization across controlled hardware ...».
- Дифференциация «hard-benign» внутри PIDS-Bench v3 в смеси не детализирована.
- Как выбирались 3 промпта LLM-рецензента и что было в остальных двух: «We compare three prompts on an independent 1,000-example development split and select one that asks for an attack probability, a binary decision, and a short rationale» — not stated.
