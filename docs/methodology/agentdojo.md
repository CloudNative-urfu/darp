# AgentDojo [arXiv 2406.13352] — методологическая разборка

Verdict: Fully portable. Всё, что нужно рецепту, — среда, сьюты, атаки, защита, логи, протокол — открыто под MIT и ставится одной командой (`pip install agentdojo`); есть тесты, CI, docs, Zenodo DOI и выпущенные логи прогонов. Единственное не переносящееся напрямую — универсальные API-модели как быстрый способ генерации данных, но для локального стека ≤8B это не блокер: интерфейс среды агностичен к модели. Ссылки: repo github.com/ethz-spylab/agentdojo (MIT; тесты в `tests/`, CI в `.github/workflows/`); docs agentdojo.spylab.ai; DOI Zenodo 10.5281/zenodo.12528188.
По-простому: авторы выложили готовую тестовую среду с 4 сьютами (сьют = набор связанных задач, итого 97 задач) и специальными атаками: враждебный текст подкладывается в ответы инструментов. Полезность и успех атаки считает программа по разнице состояний, LLM-судьи нет принципиально.
## 1. Harness
- Пакет `src/agentdojo`: ядро прогона benchmark.py, functions_runtime.py (docstring инструмента попадает в промпт), agent_pipeline/ (агент+защита как модули), attacks/, 4 task_suite'а, logging.py (JSON-логи в `runs/`), models.py (адаптеры провайдеров), CLI `scripts/benchmark.py`: «The environment specifies an application area for an AI agent and a set of available tools (e.g., a workspace environment with access to email, calendar and cloud storage tools). ... An injection task specifies the goal of the attacker (e.g., exfiltrate the user's credit card).»
- Вход модели-агента — реальные документы инструментов: «The documentations of all tools available in an environment are added to the AI agent's prompt.» [src/agentdojo/agent_pipeline/]
- Изоляция без docker/сети/браузера: среда = мутируемые объекты состояния приложения: «We implement four environments ("Workspace", "Slack", "Travel Agency" and "e-banking") and model each environment's state as a collection of mutable objects.»; LLM-судья запрещён принципиально (аргумент против ToolEmu): «This approach is problematic when evaluating prompt injections, since an injection might fool the LLM simulator too. ... if such an attack were particularly successful, there is a chance that it would also hijack the evaluation model.»
- LLM-детекторы допустимы только как тестируемая defense: «Prompt injection detection which uses a BERT classifier ... trained to detect prompt injection on each tool call output, and aborts the agent if anything has been detected»; контекст ~7000 токенов данных + 4000 токенов tools: «tasks requiring search capabilities over medium to long context windows (with up to 7,000 GPT-4 tokens for data and 4,000 GPT-4 tokens for tool descriptions)»
## 2. Источники и срез данных
- Данные синтетические «dummy»: вручную + генерация GPT-4o/Claude 3 Opus по схеме, весь LLM-вывод проверен руками: «We generate the dummy data both manually or assisted by GPT-4o and Claude 3 Opus, by providing the models with the expected schema of the data and a few examples. For LLM-generated test data we manually inspected all outputs to ensure high quality.»; чувствительных данных нет: «Intentionally Collected Sensitive Data: None ... Unintentionally Collected Sensitive Data: None»
- Сьюты: Workspace 24 tools/40 user/6 inj; Slack 11/21/5; Travel 28/20/7; Banking 11/16/9 — итого 97 user-задач, 27 inj-целей; счёт tools разъезжается: 70 — сводная таблица датасета даёт «Total samples: 124 tasks, 70 tools» — против 74: «We populate AgentDojo with total of 74 tools obtained by considering all tools needed to solve the user tasks ...»; 629 security-кейсов = кросс-произведение user×inj по релевантности (как InjecAgent): «we take a cross-product of user and injection tasks per environment to obtain the total set of security tests cases ...»; своя задача — env-класс + user-задача + inj-задача по docs «how to create new tools/tasks»: «we also provide extensive documentation on how to use our framework (including how to run the existing benchmark, create new tools, task, etc.)»; версии пинятся requirements.txt/uv.lock: «We also include a requirements.txt file that can be used to install the exact dependencies we used for the experimental results in the paper»
## 3. Протокол фиксации исходов
- Три метрики: Benign Utility (задача решена без атаки) и Utility Under Attack (решена без вредных побочных эффектов; дополнение = untargeted ASR): «Benign Utility: the fraction of user tasks that the model solves in the absence of any attacks. ... the agent solves the user task correctly, without any adversarial side effects. ... We sometimes report the complement of this value as the untargeted attack success rate»; Targeted ASR (security-функция = True): «Targeted Attack Success Rate (ASR): the fraction of security cases where the attacker's goal is met (i.e., the agent executes the malicious actions).»
- Ground truth детерминирован, траекторию не судят ни человек, ни LLM; адаптивный «any»-коллектор {A1..An}: sec-кейс успешен, если успешна хотя бы одна атака: «we consider as successful on a given security case if any of the attacks in the collection succeeds. This metric models an adaptive attacker that deploys the best attack for each user task and injection task»; DoS-семейство — отдельный файл `attacks/dos_attacks.py`
- Все траектории пишутся в JSON `runs/*` (`logging.py`), выходы всех прогонов выпущены: «We release with the code on GitHub all models outputs and conversations as JSON files, and a Jupyter Notebook that can be use to reproduce all figures and tables in the paper.» (Google Drive + ноутбук, App E.3); лидерборд agentdojo.spylab.ai/results/ и Invariant Benchmark Registry (README)
## 4. Учёт затрат
- Cost-журнала нет: точечно на GPT-4o: «We estimate that running the full suite of 629 security test cases on GPT-4o costs around US$35, and running the suite of 97 utility test cases costs US$4»; считать самим через usage провайдера или токенизатор; defense добавляет вызовов (детектор — вызов на каждый tool-выход, sandwich — повтор инструкций) — отдельной строкой → FR-1.17; Journal обязан матчить пары прогонов по ключу (suite, user_task, inj_task, defense, attack).
## 5. Статистика
- 95% ДИ на долях реализованы поверх гистограмм через statsmodels `proportion_confint`: «We report 95% confidence intervals of our experiment by using statsmodels.stats.proportion.proportion_confint either in the plots, or in the tables in the appendix when not possible in the plots»; повторы/temperature/сиды — not stated; наша схема: T=0 + k повторов → «any»-верхняя граница ASR, снапшот весов хешем (NFR-2.1/2.2).
- Benign utility с защитами: sandwich 85.5%, tool_filter 73.1% против no-defense 69.0%, детектор роняет до 41.5% — ложноположительный эффект измерим напрямую (FR-1.22); benign-ветка парная к under-attack по той же задаче (NFR-2.8).
- Позиция инъекции: ближе к концу контекста — выше ASR: «we find that injections placed towards the end of a tool's response message are most effective—with up to 70% average success rate against GPT-4o»; Slack целиком 92% из-за доли атакеро-контролируемого вывода: «attacks in our "Slack" suite have a 92% success rate ... The high success rate for this suite may be explained by the fact that attackers control a significant fraction of the tool outputs» — полю и позицию placeholder'а фиксировать схемой.
## 6. Trap-деталь
- Что ломается при reproduce: подстановка настоящих имён в шаблоны {user}/{model}: «Knowing the name of the user and of the LLM yields slightly stronger attacks, although there is a risk as incorrect guesses significantly weaken the attack» — неверное имя пользователя/модели роняет targeted ASR с 45.8% до 23.2%/23.7%, оба верных имени дают 47.7%; без реальных имён в шаблонах defense покажет фиктивную устойчивость, L* сойдётся на неверном локе.
- Между v1 и v3 статьи исправлен баг Llama-провайдера и обновлена Travel-сьют (Comments v3) — брать репо-снапшот и diff сьютов против версии статьи, иначе числа не сойдутся с опубликованными результатами.
## Прямой перенос
- Ядро сьюты: env-состояние + детерминированные utility/security + ground truth calls: «A user task further exposes a ground truth sequence of function calls that are required to solve the task.» + инъекция через placeholder'ы в реальных tool-outputs: «prompt injections are placed in appropriate places (realistically controlled by untrusted third-parties and in diverse positions of the context) that are actually queried by the model» → FR-1.10, FR-1.18 (estimator = diff до/после — «state of the environment before and after execution»), FR-1.19 (break/refused/ignored); кросс-произведение user×inj и три метрики → FR-1.19 (break = security true, ignored = utility сохранён); defense как компонент пайплайна: «AgentDojo also offers the ability to build modular agent pipelines by combining different components.» (`agent_pipeline/`) → FR-1.5, FR-1.20.
- Все промпты атак в тексте: «the "ignore previous instructions" attack ... the prompt injection from InjecAgent ... the instruction "TODO: {task description}"; and ... our "Important message" prompt»; промпты защит: «Data delimiters ... Prompt injection detection ... Prompt sandwiching which repeats the user instructions after each function call ... Tool filter which ... the LLM first restricts itself to a set of tools required to solve a given task» → FR-1.21, baselines g_simple.
## Адаптация
- Свои окружения — синтетика по своей схеме: «We populate this state with dummy, benign data meant to reflect possible initial state of the environment» — «мутируемый объект + FastAPI-подобные tools + данные с ручной проверкой LLM-генерации» → NFR-2.13; сокращение до 5 tools (FR-1.11) механику не трогает.
- Для ≤8B — паттерн вендорных доп-промптов: «For Claude 3 and 3.5 Sonnet, we additionally provide the prompt in Figure 15, as recommended by Anthropic [3]. For Llama 3 70B, we also provide the tool-calling prompt in Figure 16, adapted from [21].»; YAML-формат tool-выходов не менять (он и есть входной канал, FR-1.4): «The current runtime formats the tool outputs with the YAML format to feed the LLMs ...»; доработать `logging.py` под cost по вызову (FR-1.17).
## Непереносимо
- LLM-as-judge для utility/окружения отвергнут авторами обоснованно: «if such an attack were particularly successful, there is a chance that it would also hijack the evaluation model» — Q-метрику процесса брать только по детерминированным критериям; сравнение конфигураций без контроля позиции инъекции несопоставимо: «AgentDojo does not currently support this.»
## Копируемый CLI-набор (README, проверено)
- `pip install agentdojo` (детектор: `pip install "agentdojo[transformers]"`); прогон всех сьютов/задач: `python -m agentdojo.scripts.benchmark --model gpt-4o-2024-05-13 --defense tool_filter --attack tool_knowledge`, селект `-s <suite> -ut user_task_0` (--help описывает поля) — каркас CI.
## Чеклист переноса сьюты (дословный)
- env-класс по схеме золотых данных (env = мутируемые объекты состояния приложения); tools = python-функции с docstring; user task = prompt + utility + ground truth calls; inj task = goal + security-функция; placeholder инъекции — только в поле, реально контролируемое третьей стороной; тест валидности: ground truth воспроизводится без LLM (dummy-агент).
- Защиты: delimiting, sandwich, tool filter, детектор ProtectAI DeBERTa (библ. 45); атаки (App B.3): important message, TODO, ignore previous, InjecAgent, Max = лучшая; минимум NFR-2.8 — пары прогонов 2×2 (defense on/off × attack on/off, один task list); отчёт (u, ASR) с 95% ДИ — Парето defense vs no-defense; снапшот — релиз по Zenodo DOI: «The Zenodo-generated DOI is 10.5281/zenodo.12528188.»
