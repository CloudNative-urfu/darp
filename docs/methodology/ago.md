## 1. Harness
- Self-hosted платформа (свой API backend + web console) у IT-консультанта: данные клиента не покидают периметр; единственный outbound — заменяемый OpenAI-compatible judge endpoint (облако или self-hosted), temperature 0: «Client data must not leave the premises: all storage, scoring, and reporting run inside the client or consultant perimeter. The only outbound call is the judge endpoint, exchangeable between a cloud API and a self-hosted OpenAI-compatible runtime» / «constrained JSON call to an exchangeable, OpenAI-compatible judge endpoint at temperature 0».
- Evaluation-кейс = (вопрос, ожидаемое поведение E: reference/термины/источники, опц. retrieval-требования K*, запрещённые фразы P) плюс категория и criticality-флаг: «An evaluation case x = (q, E, K*, T, S, P) consists of a question q, an optional expected behaviour E (reference answer, expected terms T, expected sources S), optional retrieval requirements K*, and forbidden phrases P».
- Датасет версионируется; metric providers отдают {имя, значение, threshold, pass, provider}; run персистит content-hashed снапшоты датасета и профиля — решение аудируемо из тройки (датасет-snapshot, profile-snapshot, версия кода): «All thresholds, synonym policies, and judge instructions are versioned in an evaluation profile, never hard-coded: every decision is reproducible from (dataset snapshot, profile snapshot, code version)» → FR-1.18.
## 2. Источники и срез данных
- RAGBench: 100k TRACe-аннотированных трейсов, 12 датасетов / 5 доменов: «The benchmark is organised into 12 component datasets across five industry domains ... with TRACe reference labels produced by LLM annotators calibrated against human annotations»; трейсы полные — подключаются без запуска retrieval-системы: «RAGBench provides complete observed traces, so it plugs directly into AGO's evaluation contract without running any retrieval system.»
- Протокол выборок: judge-селекция на validation N=300 (3 датасета), финальный тест N=1200 (по 100 на датасет), стратифицированно и сбалансировано по adherence, фиксированные опубликованные seeds, манифесты instance-ID персистируются: «All reported numbers use stratified samples of 100 instances per component dataset, balanced by adherence label where possible, with fixed published seeds» / «Sample manifests (exact instance identifiers) are persisted, so every judge scores identical instances».
- Кэш ответов по (instance, model, rubric hash), rubric заморожена до тест-сплита, пороги не правились: «Judge responses are cached by (instance, model, rubric hash). The rubric was frozen before any test-split instance was scored; no prompt or threshold was adjusted afterwards».
- Симуляция гейта: N = 20/30/50/100/200, страты general/domain_specific/critical 0.5/0.3/0.2, базовые pass-rate 0.90/0.85/0.80, сдвиги ±0.05/0, 1000 реплик: «Candidate probabilities change by −0.05, 0, or +0.05 in every stratum, defining the regressed, unchanged, and improved scenarios. For each scenario and N, we run 1,000 replicates with data seed 20260709» → NFR-2.9; до прогона чистим дубликаты/слабые кейсы/дыры покрытия/privacy-findings, blocking-находка отменяет гейт целиком: «Evaluation datasets are curated before any gate run: duplicates, weak cases, coverage gaps, and unresolved privacy findings are surfaced, and blocking findings prevent the gate from running at all.»
## 3. Протокол фиксации исходов
- Четырёхсостоянийная lattice по кейсу (not evaluable / block / manual review / promote) и консервативная агрегация по run'у (Eq. 1–2): «The set C is a fixed system safety floor: membership in C takes precedence over a per-metric profile mode and therefore blocks even if that metric was mistakenly configured as observe-only».
- Фиксированное множество критических метрик C (нет контекстов, source/version mismatch, forbidden phrase, PII, secret, injection, format-нарушение) эскалирует независимо от режима профиля: «A fixed, documented set C of critical metric identifiers (missing required contexts, failed source or version matching, forbidden phrases, PII, secret, or injection findings, output-format violations) escalates independently of mode»
- Четыре типа evidence — observed / declared / inferred / missing, а missing → явный gap с impact-стейтом, никогда не дефолтное значение: «No implicit pass: absent evidence can only produce not evaluable or manual review, never promote» — absent evidence даёт только not evaluable или manual review, не promote [Eq. 2] → FR-1.19.
- Протокол судьи: значение вне [−0.01, 1.01] — protocol error → метрика failed → кейс manual review; malformed output никогда не coerced; adherence не скорится для turn'ов без retrieval: «Malformed judge output is never coerced to a valid score.» / «adherence is scored only for cases that require retrieval; for purely conversational turns the dimension is undefined and omitted rather than imputed»
## 4. Учёт затрат
- Judge-cost в долларах per прогон: gpt-4.1-nano $0.39 / gpt-4o $9.42 на тесте (N=1200), на селекции $0.06 против $1.36 → NFR-2.9: cost отдельной строкой, не в скорах; latency/токены как метрика гейта — not stated; операционная экономика review-vs-block качественна: «an unnecessary manual review costs consultant time, while a silently promoted regression costs a production incident.»
## 5. Статистика
- Стратифицированный бета-биномиальный гейт: per-stratum posterior Beta(α0+k, β0+n−k), equal-tailed 95% credible intervals: «observing k successes among n cases gives the posterior Beta(α0 + k, β0 + n − k), reported with equal-tailed 95% credible intervals per stratum»; run — взвешенная posterior mean; регрессионный риск ρ = P(pB < pA − δ | data), δ=0.03; гейт: ρ ≥ 0.8 → block, ρ ≥ 0.5 → review, иначе promote: «the statistical gate returns block if ρ ≥ τb, manual review if ρ ≥ τr (defaults 0.8, 0.5), and promote otherwise» → вероятностная форма FR-1.24.
- A/B — Monte Carlo на 121 posterior-сэмпл (seeds 4201/4202): «121 posterior samples, and independent posterior streams seeded at 4201 and 4202»; базовая пара независима, поэтому при общих item'ах дисперсия разности завышается → гейт сознательно консервативен к review/block: «When they share items, positive correlation means independence overestimates the variance of the difference, so the gate errs toward manual review and block» → NFR-2.8.
- Мета-оценка судьи обязательна до влияния на решения: golden set ≥30 (smoke) / ≥100 (decision-grade), обе классы, minority ≥30%, двойная независимая аннотация + арбитраж, IAA (raw agreement, Cohen's κ, MCC, AUROC) как потолок, 95% bootstrap CI: «at least 30 cases as an absolute floor for a smoke-level check, and 100 or more for decision-grade validation; both classes present for every dimension (minority class ≥ 30%)» / «independent labelling by two annotators with adjudication, and inter-annotator agreement reported as the ceiling against which judge agreement is read».
- В block-режиме — минимальный lower-bound и максимальная ширина интервала из профиля; смена endpoint/версии инвалидирует отчёт: «A judge-dependent metric may run in block mode only when its validation report meets the profile's minimum lower-bound and maximum interval-width criteria.» / «switching judge endpoint or model version invalidates the report and re-triggers the protocol.».
## 6. Trap-деталь
- Что ломается при reproduce: тихая недостоверность судьи — gpt-4.1-nano дал ноль protocol errors и правдоподобные объяснения, но AUROC 0.603 [0.570, 0.634] — чуть выше случайности: «Nothing in its operational output signals this: across all runs it produced zero protocol errors and well-formed, plausible explanations»
- Вторая ловушка похожа: pilot N=300 дал AUROC 0.563 [0.495, 0.631] — интервал включает chance, вывод невозможен без CI: «That interval includes chance, which is why the framework mandates confidence intervals before conclusions are drawn»; верифицируемый вердикт — только от полного run.
## Прямой перенос
- Четырёхсостоянийная lattice по кейсу/run (Eq. 1–2) — шаблон фиксации break/refused/ignored с разделением «не измерено» от «измерено плохо» → FR-1.19, FR-1.18; критическое множество C, эскалирующее поверх per-metric режимов → FR-1.5 + FR-1.19 [Eq. 1–2].
- Beta-binomial гейт с ρ, δ и stratum-заготовками (general/domain/critical) → FR-1.24 (вероятностный L*), FR-1.23; мета-оценка судьи с golden set и IAA-потолком → FR-1.22 (FP = ложные срабатывания судейской части).
## Адаптация
- Страты категорий → страты трафика полигона (attacker-кейсы vs легитимные → FR-1.1, FR-1.23); «manual review» → ручная очередь возвратов: гейт как механизм эскалации, не вердикт: «No implicit pass : absent evidence can only produce not evaluable or manual review, never promote . Human-in-the-loop by construction : the gate is an escalation mechanism, not an autonomous verdict» → FR-1.15, FR-1.19.
- Judge-cost в долларах + взвешенные stratum-веса под traffic-доли → FR-1.17, NFR-2.9: «profiles may therefore supply explicit target weights (traffic shares or business criticality) when a production-facing estimate is required, and the report states which weighting is in effect»; фиксированные seeds (данные 20260709, posterior 4201/4202) → NFR-2.8; симуляционный дизайн «naive gate vs decision-grade» — методика сравнения бейслайнов g0/g_proc/g_simple → NFR-2.12.
## Непереносимо
- Проприетарный engagement-контур и платформенный frontend — переносится только decision-и-статистический слой; судьи — только cloud-модели уровня gpt-4.x: «only outbound call is the judge endpoint, exchangeable between a cloud API and a self-hosted OpenAI-compatible runtime» — для ≤8B self-hosted нужен свой golden set заново (protocol оставляем, NFR-2.6).
