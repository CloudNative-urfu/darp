# RAGWarrant [arXiv 2609.34179] — методологический разбор
Вердикт: **Полностью переносимо.** OSS (Apache-2.0), тегированный артефакт v0.1.1-rc1 (коммит зафиксирован), воспроизводится свежим клоном в hardened Docker-джобе, принимает внешние экспорты эвалюаторов, проверяет целостность артефактов: «The tagged artifact reproduces from a fresh clone, runs as a hardened Docker job, accepts external evaluator exports, and verifies artifact integrity.» Рецепт копируется целиком; исходные датасеты — под лицензиями, их добор не меняет методику. Код: https://github.com/RAGWarrant/ragwarrant-governance
По-простому: Это фреймворк для запуска честной оценки защиты: правила решения (что считать победой) объявляются заранее и замораживаются, метрики импортируются из внешних эвалюаторов, каждое решение — одно из четырёх (PROMOTE/BLOCK/REJECT/INCONCLUSIVE) с журналом и хэшами.
## 1. Harness
- Единица работы — декларативный governance suite: кандидат + базовая политика, роли сплитов (dev / sealed confirmatory), направление и состав метрик, noninferiority-маржа δ, operational-цели, жёсткие дисквалификаторы, protected-слайсы, класс evidence, ожидаемые артефакты: «A governance suite is configured as a declarative contract. It identifies candidate and baseline policies, development and held-out split roles, metric direction and composition, the noninferiority margin, operational objectives, hard disqualifiers, protected slices, evidence class, and expected artifacts.» Логика селектора замораживается ДО оценки confirmatory-сплита: «Candidate generation may be exploratory, but selection logic is frozen before a confirmatory split is evaluated.»
- Метрики импортируются адаптерами (Ragas-, DeepEval-, LangSmith-, Phoenix-подобные + generic CSV/JSONL) в каноническую схему: «Normalization is intentionally explicit. Each imported metric retains its evaluator name, group, direction, scale, split, policy ID, and source-artifact hash. Scores are not treated as interchangeable merely because they share a 0-to-1 range.» Телеметрия — раздельные поля: «Operational telemetry follows the same principle: modeled cost, measured latency, API-call count, and context volume remain distinct fields so that a favorable weighted utility can be decomposed during review.»
- Прогон — конечный контейнер: вход — политики + санитизированные датасеты/экспорты, выход — promotion_decision.json (run_id, класс решения, селекция, дельты quality/cost/latency, risk_flags, хэши); в охвате статьи — hardened Docker: «The finite job contract accepts policy configurations, sanitized datasets or evaluator exports, and operational telemetry; it emits a promotion decision, run manifest, policy summaries, selector comparison, claim update, validation report, and optional audit bundle.»
- Воспроизводимость и публикационные тесты: «A fresh Git clone installed and reproduced the public-mini workflow without private data or model credentials; the hardened Docker job completed under the constrained runtime profile; and verify-run confirmed artifact hashes, schemas, and hygiene conditions.» GitHub CI гоняет publication-тесты: «GitHub CI executes publication tests and claim checks on the public tree.»
## 2. Источники и срез данных
- Датасеты: T2-RAGBench — 1,142 запроса (dev); MultiHop-RAG — 331, sealed confirmatory; CRAG web — 2,706 строк / 9,848 web-документов / 571 confirmatory + mock API (tool-routing: live + frozen); HotpotQA — 1,000 локальных + 249 confirmatory behavioral; public-mini — синтетика для репродукции: «T2-RAGBench supplied a larger text-and-table development path; MultiHop-RAG provided a fresh sealed multi-hop confirmatory corpus; CRAG enabled both corpus-backed retrieval and a mock-API routing environment; and HotpotQA added answer labels and supporting-fact annotations.»
- Сплиты режутся детерминированной группировкой + дубликат-чек; confirmatory-unlock отказывается при провале provenance/leakage/evidence-предусловий: «Split construction used deterministic grouping and duplicate checks where supported, and confirmatory unlocks were refused when provenance, leakage, or evidence prerequisites failed.» Репо несёт манифесты/хэши/processed-метрики, не raw текст: «The public repository carries manifests, hashes, and processed metrics rather than raw licensed text.»
- Генеративные модели — pinned через Ollama: «Generative studies used pinned local models through Ollama and stored prompts and answers outside the public tree. Public rows retained hashes, lengths, policy identifiers, evaluator scores, and operational telemetry.» «The program tested qwen3:8b, gpt-oss:20b, and llama3.2:3b in bounded slices» — промпты и ответы вне публичного дерева, только хэши/длина/ID/скоры/телеметрия → NFR-2.6.
## 3. Протокол фиксации исходов
- Главное правило — промотируемо только при прохождении всех hard gates; если интервал пересекает порог → INCONCLUSIVE, а не «победа»: «Promotion is permitted only if all hard gates pass.» «PROMOTE(p) ⇔ hard_gates(p) ∧ LCB(Δq) ≥ −δ ∧ [UCB(Δc) < 0 ∨ UCB(Δl) < 0].» «If uncertainty crosses a gate, the decision is INCONCLUSIVE rather than a win.»
- Четыре научных решения — PROMOTE / BLOCK / REJECT / INCONCLUSIVE, отдельные runtime-ошибки в схеме: «The deployable job exposes four scientific decisions: PROMOTE when evidence supports replacement within scope; BLOCK when the decision cannot be evaluated safely; REJECT when evidence favors retaining the baseline; and INCONCLUSIVE when available evidence does not resolve the gate. Runtime errors are recorded separately in the machine-readable schema.» Hard gates non-compensatory: «Hard gates are non-compensatory. Leakage, missing provenance, security disqualification, publication-hygiene failure, or an absent quality signal cannot be offset by lower cost.»
- Evidence-классы с claim ceiling (fixture → development → confirmatory → frozen-derived → generative → human → platform → production); слабая evidence не переподписывается вверх: «The evidence ladder therefore sets a claim ceiling: evidence may support a narrower statement than its maximum, but never a broader one.» Append-only ledger накапливает отрицательные и blocked исходы: «A historical ledger preserves positive, negative, blocked, refused, and superseded outcomes, while verify-run checks required artifacts, schemas, and hashes.»
## 4. Учёт затрат
- Стоимость консерватизма фиксируется: blocked-rate и promotion-rate документируются рядом с quality-результатами: «Fail-closed behavior is costly: a conservative controller can retain an expensive baseline or delay a useful change. The packaged artifacts therefore record blocked rate and promotion rate alongside quality outcomes.» Единицы: modeled operational-cost (не доллары, если артефакт не объявил иное), latency, calls, context volume: «Unless an artifact declares otherwise, cost is a normalized or modeled operational-cost field rather than a dollar-denominated cloud bill.»
- Дельты парные и покомпонентные: HotpotQA quality −0.0408 / F1 −0.0843 / cost −2.3301 / calls −1.9839 → BLOCK; CRAG behavioral quality −0.00515 / cost −2.368 / calls −1.799 — все четыре поля в одном решении → NFR-2.9.
## 5. Статистика
- Парный bootstrap + win/tie/loss при наличии example-level пар; grouped-interval публикуется только отдельно реализованным; noninferiority-маржа δ ≈ 0.01 по композиту объявляется в конфигурации до рана → FR-1.24: «Where paired example-level evidence existed, analyses used paired bootstrap intervals and win/tie/loss summaries. Grouped intervals were reported only when separately implemented. Noninferiority margins, often 0.01 for a composite quality score, were declared in configuration.» Статистика подчинена validity: «Statistical output remained subordinate to evidence validity: a narrow interval cannot rescue duplicated rows, a constant quality signal, invalid provenance, or confirmatory leakage.»
- Audit-эпизод: нулевая ширина bootstrap: «An early offline public real-RAG grouped-split run reported RAG Compass ahead of a validation-selected baseline by 0.0488 with a zero-width bootstrap interval. The result appeared precise because 49,850 paired example-seed rows were available across 4,985 unique examples and 10 seeds.» «A row-level reconstruction found only one unique paired delta»; run понижен до дескриптивного, добавлены проверки nonconstant-сигнала: «The episode motivated three changes: checks for nonconstant paired signals, refusal to report one bootstrap under multiple labels, and a historical evidence ledger that can narrow a prior claim without deleting the record.»
## 6. Trap-деталь
- Где застревает повтор: положительный CRAG-generative слайс (12 примеров) не воспроизвёл cost-результат: «The effect was not stable. Three deterministic repeats did not reproduce the cost result; a second model produced usable signals without positive cost slices; and a smaller instruct model repaired blank-answer behavior without creating a repeatable efficiency win.»
- Выгода оказалась в основном от cost-поля, не качества: «ablation attributed nearly all of it to declared cost and a small latency difference, not raw-quality improvement.»
- Thinking-mode гасит usable answers, blank-answer rate, parse success — всё вводится как ГЕЙТЫ, а не как ошибки политики: «Treating generator availability, parse success, and quality-signal variance as gates prevented these failures from being mistaken for policy evidence.»
## Прямой перенос
- Декларативный suite-контракт (candidate/baseline/сплиты/δ/hard gates/protected slices/evidence class) → FR-1.5, NFR-2.12; четырёх-исходная таксономия + append-only ledger с отрицательными исходами → FR-1.19.
- Правило LCB(Δq) ≥ −δ ∧ UCB(Δc) < 0 — прямой аналог «не хуже по качеству (L*) при выигранном cost (C_guard/C_ep)» → FR-1.24, NFR-2.9; раздельные поля cost/latency/calls/context внутри одного решения → FR-1.17; адаптеры нормализации внешних метрик с provenance/hash → каркас сбора состояния из разнородных экспортов → FR-1.18.
## Адаптация
- Evidence-классы + claim ceiling наложить на пять бейслайнов g0/g_proc/g_simple: каждому — evidence-класс и потолок утверждения → NFR-2.12.
- Fail-closed HotpotQA (операционный выигрыш при quality loss → BLOCK) — шаблон интерпретации R-vs-Q trade-off в двухстороннем контуре → FR-1.23: «The governed policy reduced retrieval cost, context volume, and calls, but answer quality declined beyond the declared noninferiority margin. A conventional efficiency report could describe the run as a cost win; RAGWarrant classified it as operational gain with quality loss and withheld promotion.»
- Проверки nonconstant-signal/дубликатов перед CI → NFR-2.8; Docker-джоба + verify-run — механика заморозки defense-конфигурации и paired-запусков → NFR-2.8, NFR-2.4 (уже OSS).
## Непереносимо
- Cost-модель modeled/нормализованная, не платёжная; полигону нужны долларовые C_guard/C_ep → NFR-2.9 требует перекалибровки.
- CRAG — noncommercial; без добора исходников слайс не воспроизводится: «Few public corpora support full, policy-dependent, corpus-backed evaluation in the packaged program; CRAG also carries noncommercial-research restrictions.» «Reproducibility artifacts verify code paths, decisions, and public hygiene; they cannot independently verify licensed raw data that are excluded from the repository. Exact external replication therefore depends on acquiring the original corpora and reconstructing the declared manifests.»
## Что осталось непонятным
- Как строится composite quality score при смешанных метриках — «объявляется в конфигурации», веса не показаны: «A suite may combine them into a declared composite, use them as separate hard gates, or retain them only for diagnosis» — not stated.
- Целевой promotion-rate/blocked-rate для калибровки консерватизма не предложен: «The current evidence does not estimate an optimal false-promotion versus false-refusal trade-off; it establishes that the framework can encode a conservative policy and preserve the cost of that conservatism for later study.»
- Конструкция «249 confirmatory behavioral rows» (HotpotQA) описана только инлайн, отдельной таблицей нет — not stated.
