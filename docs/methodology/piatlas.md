# SoK: PIAtlas / PICorpus [arXiv 2610.24999] — методологическая разборка
Verdict: Fully portable (для роли «источник атак и разметки»).
По-простому: Авторы собрали большой открытый корпус атакующих запросов и промптов для его разметки: каждая запись получает метки по таксономии (6 классов, 34 техники) и цитату-доказательство.
## 1. Harness
- Это обзор (SoK), а не среда прогонов, но весь артефакт открыт MIT: таксономия JSON, 8,663 размеченных шаблона, промпты разметки с SHA-256, кроссвок 44 схем, скрипты пересчёта всех таблиц, замороженный сбор корпуса; репо: github.com/stevendamianakis/piatlas, сайт: stevendamianakis.github.io/piatlas-site: «All artifacts are available at https://github.com/stevendamianakis/piatlas … and scripts that regenerate every number and table in this paper from the frozen corpus build that the repository contains. No part of the corpus is withheld.»
- Разметка запускается run_labeling.py (Claude Code CLI, headless, без tools/MCP; run_config.json хранит модель, флаги, SHA-256 промптов, всё в README репозитория): «Claude Opus 5.5 with medium effort ran through Claude Code 2.1.281 in headless mode, with no tools and no MCP servers, one record per call (batch size 1, chosen by the calibration rule in run_labeling.py), in a fixed seeded order.» «run_config.json holds the model, the CLI flags and each prompt's SHA-256.»
- Промпты разметки и логи вызовов лежат в репо: «`L/run_labeling.py`; progress logs `L/full*.log`; raw model output of every call in `L/calls*.jsonl.gz` (session identifiers removed).»
- Эмбеддинги F2LLM-v2-14B + Qwen3-Embedding-8B без обрезки (макс 16,384 токенов): «run the encoder in bfloat16 on a single GPU, and do not truncate inputs (the maximum sequence length is 16,384 tokens).»
- Кластеризация: batch 1024, k=33; GMM diag; HDBSCAN min_cluster_size 15: «k-means is MiniBatchKMeans on L2-normalized embeddings (batch 1024, k=33, the number of techniques that occur in the labels).» «The Gaussian mixture uses diagonal covariances.» «HDBSCAN uses min_cluster_size=15, and its noise points count as one cluster.»
- Карта PCA→50→UMAP (seed 42), k по silhouette 8–40 → k=10: «The map is PCA to 50 dimensions, then UMAP (15 neighbors, min_dist 0, seed 42), then k-means with k chosen by silhouette over 8–40.»
## 2. Источники и срез данных
- Собрано 20 публичных MIT-датасетов (2022-01…2026-05): из 868,374 записей побайтовым дедупом по «operative field» (без фолдинга юникода) убрали 423,876 дубликатов (48.8%), осталось 444,498 уникальных; приоритет кураторских источников перед объёмными: «Keys are compared byte-exact (no Unicode or whitespace folding), and we keep the first occurrence under a fixed source-priority order that places curated and human-authored datasets ahead of the high-volume algorithmic and competition corpora.» «Across the 868,374 ingested records this removes 423,876 exact duplicates (48.8%).»
- Из записей сделано 63,529 шаблонов (58,866 LLMail-Inject + 4,663 прочих); delivery 64.1% direct / 35.9% indirect, авторство 95.8% human, 88 сред успеха; метки успеха с конкурсов: LLMail-Inject 2,027/148,514 (1.4%), SaTML CTF 2,354/47,682 (4.9%): «A subsequent per-dataset templatization pass factors records into template and payload where a reusable template is identifiable, yielding the 63,529 distinct templates of Table XI.» «Delivery, authoring (human or algorithmic), application environment, and each source's own labels are kept as metadata, not as part of the PIAtlas axis.»
- Размечено 8,663: 4,663 кураторских из 13 бенчмарков + 4,000 адаптивных LLMail (seeded Phase-1; срез 66,723 из 127,376; Phase 2 исключён; bias — перевес записей, триггеривших API): «We label two partitions of PICorpus, 8,663 records in all, chosen for coverage rather than volume. The curated partition holds all 4,663 templates outside LLMail-Inject, which come from thirteen benchmarks, and the adaptive partition is a random sample of 4,000 Phase-1 LLMail-Inject templates, which represent adaptive attackers who faced a live defense.» «The LLMail-Inject templates cover only the first 66,723 of the 127,376 Phase-1 submissions (the first pass of the labeled release), including every submission marked as having triggered the email API. Phase 2 is excluded, so the adaptive partition over-represents API-triggering submissions.»
## 3. Протокол фиксации исходов
- Таксономия: 6 классов F1–F6, 34 техники, 131 субтехника; multi-label по signature, только по тексту — интенцию не угадывают; порядок сигнатур F3 → F2 → F6 → F5 → F4 → F1 (последней): «The hierarchy currently has six classes, 34 techniques, and 131 sub-techniques.» «Each class has a signature, a test that an annotator can check on the text alone, without guessing the attacker's intent.» «They first decode any hidden text (F3), because the other tests must read the decoded instruction. They then check F2, F6, F5, and F4, and assign F1 last.»
- Комбинации — норма (Finding 1): медиана 2 класса / 3 техники, 77% записей ≤2 классов, >5 не встречается: «Multi-label composition is the norm. The median curated template spans 2 classes and 3 techniques, and 38.3% are single-class. But the stack is shallow, as 77% of curated templates draw on one or two classes, and none on more than five.» Промпт v1.0→v1.1 «общая просьба ответить подробно — не F6» (478 кураторских F6 переразмечены): «A general request to answer carefully or in detail, with no prescribed form, is not output coercion, because F6 requires a hard constraint on the literal output.» «Prompt v1.1 adds one rule: a general request to answer carefully or in detail is not F6. The 478 curated templates whose first labels carried F6 were relabeled with v1.1 (labels_f6_recheck.jsonl).» Каждая метка несёт цитату-доказательство (>99.5% дословно): «Every production technique label carries an evidence quote. Over 99.5% occur verbatim in the record.» Batch выбран калибровкой на 64 записях: batch 1 → 0.97 (при batch 4/8 — 0.94, техники 3.5→3.3): «Two runs on a 64-record calibration sample agree at a micro-F1 of 0.99 over class sets and 0.97 over technique sets (Table III).» «We chose the batch size by a calibration on 64 records before the full run, and a prompt cached across calls kept the labeling cost low.»
- Человек-верификация: 300 записей (150 curated + 100 LLMail + 50 oversample F3/F5/F6), сид фиксирован, референс-метки blind: «The sample contains 300 records (3.5% of the labeled set), drawn with a fixed seed. It holds 150 curated templates stratified by source (at least two per source), 100 LLMail-Inject templates drawn uniformly, and 50 records oversampled from those whose production labels carry obfuscation, scenario framing, or output coercion, so that every class has support.» Production vs человек: micro-F1 0.97 (классы) / 0.92 (техники), κ 0.95: «Against the first-author human reference, the production labels reach a class micro-F1 of 0.97 on the sample (95% interval 0.97 to 0.98).» «The two label sets agree on 97.7% of the 1,800 binary class decisions (κ=0.95).»
- Классовые доли правятся поправкой — weighted-средняя разности human/production: «The correction adds the weighted mean difference between human and production labels on the partition's sampled records.» DI95 = percentile bootstrap 2,000 репликатов, стратифицированных по слоям выборки: «95% intervals are percentile intervals from 2,000 bootstrap replicates that resample within the sampling strata.»
## 4. Учёт затрат
- В репо лежит полный лог разметки и run_config.json — в README перечислены артефакты: «`L/run_labeling.py`; progress logs `L/full*.log`; raw model output of every call in `L/calls*.jsonl.gz` (session identifiers removed).» Эмбеддинг 4,663 шаблонов считается <30 минут на одной GPU 96 ГБ RTX PRO 6000 (секция отчёта об использовании LLM): «The embedding models (F2LLM-v2-14B and Qwen3-Embedding-8B) are open-weight LLM-based encoders that ran on a single 96 GB workstation GPU (NVIDIA RTX PRO 6000), where each embedding pass over the 4,663 templates took less than half an hour.» Cost разметки статьи не публикуются — только время/объём; рецепт для полигона: дешёвая модель для тегирования + калибровка batch 1/4/8 на 64 записях; при «a prompt cached across calls» делить цену на число записей: «We chose the batch size by a calibration on 64 records before the full run, and a prompt cached across calls kept the labeling cost low.»
## 5. Статистика
- Кластеризация прогнана на 5 сидов k-means (0, 1, 2, 3, 42) × 10 инициализаций, NMI/ARI/AMI пересчитаны заново: «The five-seed runs use seeds 0, 1, 2, 3 and 42 with 10 initializations each.» Контролы: группировка по бенчмаркам (Finding G1) и no-ASB-прогон (rerun_no_asb.py): «Grouping by benchmark as a baseline (App. C, Finding G1)» «Cluster recovery (Tables VII and XIII), five seeds, no-ASB ranking» По бенчмаркам как baseline: «Because benchmarks reuse techniques, this grouping already agrees with the class+technique sets at NMI 0.47, ARI 0.23, and AMI 0.40.»
- Классовые доли с 95% DI: F2 35.3%→33.8% после поправки; F3/F4 адаптивного среза выше кураторских, поправка ≤7.3 пп: «The correction adds the weighted mean difference between human and production labels on the partition's sampled records.» Finding 4: F2 +41.7, F3 +58.6, F4 +31.8, F5 −7.9: «Structural spoofing appears in 76% of its templates versus 35% in curated data, obfuscation in 69% versus 5%, social engineering in 67% versus 29%, while instruction manipulation stays near-universal and scenario framing falls from 14% to 4%.» Другие прогоны: human-верификация с весами включения против 300-записного sample; энкодеры f2llm_plain / f2llm_steer / Qwen3-8B: «The plain variant and the comparison encoder Qwen3-Embedding-8B use unprompted encoding.» UMAP seed 42: «projects these with UMAP (15 neighbors, minimum distance 0, Euclidean metric, seed 42).»
## 6. Trap-деталь
- Где застревает повтор: production-метки недетерминистичны (закрытая модель при rerun даёт новые метки) — anchor при переносе = выпущенные метки (piatlas_v4_curated_4663.json / llmail_4000.json.gz), а не re-run (объяснение в README репо): «This needs the Claude Code CLI; the model is closed and not deterministic, so a rerun gives new labels.» «The model is closed, so the labels are not reproducible by re-running it, which we mitigate by releasing every label and prompt so that the labels can be audited and re-derived with any model.»
- Без двух неочевидных правил повтор ломает разметку: placeholder вместо payload = «голая команда» (F1.T1); «ответь подробно» без жёсткого формата — не F6: «The placeholder that replaces the payload counts as a plain command (F1.T1) unless the template embeds, rewords, or hides the request. A general request to answer carefully or in detail, with no prescribed form, is not output coercion, because F6 requires a hard constraint on the literal output.» Пропустишь их — авто-разметка переприсвоит F1/F6 почти каждой записи, и классовые доли полигона изменятся.
## Прямой перенос
- Матрица «бенчмарк × класс» + метка Cov. + правило «бенчмарк публикует свою строку матрицы» → обязательный отчёт FR-1.21; Finding 3 (agent-бенчмарки покрывают 2–4 из 6 классов) как checklist.
- Кураторская (4,663) + адаптивная (4,000) партии — готовый seed-поток атак (с oversample F3/F5/F6 против skew) → FR-1.21/NFR-2.8.
- Формат записи «template + payload + метки + цитата» → каркас записи атак; промпт-разметка с цитатами-доказательствами → FR-1.19; multi-label композиция (Finding 1): считать по классам, не по записям → FR-1.21; Finding 4 (adaptive атакеры завышают F2/F3/F4) → NFR-2.8: парные прогоны — baseline без дефенса vs с ним.## Адаптация
- Свои доли классов (аналог Finding 4 по долям классов) с порогом 5% до округления, аналог Cov.; метки своих атак — промптом из репо разметки + калибровка на 64 записях, anchor = свой запуск, не чужие метки.
- User-side vs attacker-side из InjecAgent на ту же рамку; добор F3/F5/F6 до нескольких сильных шаблонов на класс.
## Непереносимо
- Лейблер — закрытая модель (Claude Opus 5.5, medium effort, Claude Code CLI), rerun нестабилен: разметку полигона делать на open-модели, anchor = свой запуск + калибровка.
- Техника-наборы шумные: идентичны только у 56% записей — анализировать по классам (micro-F1 0.97), не по наборам (0.92); межаннотаторская надёжность не измерена (один аннотатор): «Technique sets reach a micro-F1 of 0.92, but only 56% of records receive identical technique sets, so analyses conditioned on a single technique should allow for this noise.» «There was no second human annotator, cross-verification, disagreement resolution, or adjudication. Accordingly, we do not report inter-rater reliability between human annotators.» F2LLM-14B требует GPU 96 ГБ — конфликт с лимитом «≤8B локально» (NFR-2.4/2.5): взять маленький энкодер + своя калибровка silhouette; геометрия кластеров (Findings G1–G3) не переносится 1-в-1.

- Batch-описание PICorpus «5000+ payload и 42 mechanisms» противоречит v1 статьи: 444,498 записей, 8,663 размеченных, 34 техники, 131 субтехника — возможно другая версия SoK, зафиксировать по v1 (2610.24999v1): «The result, PICorpus, contains 444,498 distinct attack instructions and is released under the MIT license as a single compilation.» «The hierarchy currently has six classes, 34 techniques, and 131 sub-techniques.»
- Адаптеры, собравшие исходные датасеты (до datasets_merged/output), в дереве репо не видны.
- Полный список лицензий 20 датасетов не проверен построчно.
